# 默认自动保存、cwd 分组与会话内存模式

状态：已接受，随 07 票实现。

新会话默认进入自动保存模式：全局 agent 目录下的 `sessions` 根按有效 cwd
分组，每个对话以 SDK conversation ID 与创建时间命名独立文件。显式
`--session-dir` 替换存储根并直接在该目录放置文件；`--no-session` 使用内存
会话。空会话保持 `pending`，首个真实用户活动（user／assistant 消息，或
`!`／`!!` 使用的 custom 提交）才建立目录与文件。相比选择时即建文件，这避免
只打开应用就留下空文件，代价是首个写入需要一次延迟创建；custom 提交也必须
触发保存，否则仅运行用户 shell 的新对话会丢失记录。

cwd 分组名保留可读的路径片段并附上完整路径的短摘要，因此不同工作目录不会
因清理后的名称相同而共用一个目录。分组只是默认根下的落盘布局，不是可解析的
标识；读取方以 header 的 cwd 为准。

会话公开 `save_mode`（`auto`／`memory`）与既有 `save_state`
（`pending`／`saved`／`unsaved`）。内存模式不自动写入、不自动救援，退出后不
自动恢复，保持 `pending` 但不影响接纳；退出前仍可显式 `save(path)`／
`export(path)`，`save(path)` 绑定该文件后恢复自动追加。相比把所有会话都写成
文件，这给出一致的可解释状态，同时不改变 Agent 是完整历史唯一权威的边界。

文件布局只服务于本产品：版本 1 JSONL 头、完整 SDK 记录与 SDK 校验恢复不变；
不承诺与其他产品会话文件互读。单写者锁与原子完整替换见
[稳定路径锁决定](0007-session-writer-ownership.md)；发现、持久命名与
`sessionDir` 设置消费由各自契约维护，本决定只描述保存布局。
