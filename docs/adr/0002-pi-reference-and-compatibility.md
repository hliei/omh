# 固定 pi 参考基线并对齐概念与 API

Python SDK 固定参考 [pi 提交 f9bcd351dc3cedf989bc5fc0f8aa012db5737df2](https://github.com/earendil-works/pi/tree/f9bcd351dc3cedf989bc5fc0f8aa012db5737df2)，以已交付能力为范围依据、规范为行为依据；文档与实现冲突时逐项明确，不默认复制缺陷，后续更新基线作为显式变更处理。

首版承诺核心概念与公开 API 对应，暂不承诺会话文件及远程协议互操作。这允许保留 pi 的使用模型而独立选择 Python 表达与存储实现，避免在上游仍有未完成能力时承担完整互操作成本；未来若需要两种实现共享会话或直接通信，必须重新评估兼容约束。

内建持久化 Value 与 ValueList 地址使用 `omh.*` 命名空间，不沿用上游的 `pi.*`；应用自定义地址不受限制。这些地址属于本项目的存储格式，使用项目自身前缀可避免暗示与 pi 会话文件互操作。首版发布前不为 `pi.*` 提供读取别名或迁移层；未来若需读取其他实现或旧版本写入的数据，再通过显式格式迁移处理。

文件职责与主要函数尽量对应上游，便于人工核对；不将不同职责集中到大文件。保留核心类名，方法和字段使用 Python snake_case，以 async/await 为主，首版不另设同步 API。必要的 Python 结构调整应说明对应关系与差异，结构可追溯性优先于另起一套内部架构。

保留 harness 的显式调用 Context 及其传递边界，将调用者取消与持久化任务取消分开：调用者停止等待不自动取消共享执行，也不写入任务取消状态；request_abort 才请求持久化取消。此 Context 为进程内调用上下文，不进入持久化数据。Python 异步取消的适配必须保持这一边界。llm 层另保留上游同名的 `omh.llm.Context`，它承载消息、系统提示和工具定义，是模型请求输入，不承担 harness 调用取消语义。

保留 Result / Ok / Err 及上游错误通道，区分预期接口错误、operation 执行结果和运行时故障，避免将接口错误统一改成异常而增加核对成本。内部数据以 dataclass 和类型标注表达，接口使用 Protocol；显式处理持久化编解码与不可信输入校验，保持上游信任内部类型化对象的边界。
