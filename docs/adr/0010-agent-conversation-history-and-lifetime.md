# Agent 的对话历史与实例生命周期

状态：已接受并实施。完整历史、隔离投影、idle 恢复、活动与取消协调、压缩／重试、永久 close 及终结 prompt 链已交付。coding-agent 已交付完整 JSONL 往返、保存故障后的暂停与修复、先准备后关闭的切换及旧历史／队列保留。沿用 [ADR-0009](0009-agent-runtime-policy-ownership.md) 的统一运行时入口；当前行为见 [Agent 契约](../agent.md)和[应用契约](../../coding_agent/README.md)。

Agent 持有当前对话完整历史的进程内权威版本，宿主负责保存与读取。压缩保留原始历史并追加压缩记录，SDK 据此构建后续有效上下文。相比由宿主持有权威历史、Agent 只持有效上下文，这一选择减少运行状态与历史之间的同步边界；相比用摘要替换原始历史，它保留展示和追溯材料。代价是完整历史占用进程内存，保存数据也不因压缩而自动缩小。

一个 Agent 实例绑定一份对话，可以执行该对话的多次运行和压缩。coding-agent 切换应用会话时创建或恢复另一个 Agent，再切换引用。相比让同一实例装入不同对话，这一选择以实例边界区分历史、队列与运行状态，减少旧运行结果混入另一对话的协调成本；应用承担实例组装和订阅重绑。

稳定会话身份及记录标识随完整历史的所有权进入 SDK，保存与恢复保持它们；新建对话建立新身份。coding-agent 管理文件路径、工作目录、展示名称与文件格式元数据。相比仅由应用文件头持有会话身份，这保留已有稳定身份的含义并使纯嵌入场景也能保存完整对话。模型请求选项 session_id 保留宿主指定的语义，与历史身份区分；宿主可以选用同一值，SDK 不由此要求二者相同。

切换先完成新实例的文件读取、解码、SDK 校验与构造，再关闭旧实例并发布新引用。准备失败或取消时旧实例仍可使用，备用实例在切换完成前不执行工作。相比先关闭旧实例再准备，这增加一个暂时存在的备用对象，使可失败的准备发生在旧实例永久失效之前；两实例不同时执行。开始关闭旧实例后，应用拥有剩余切换收尾；取消调用方只停止等待，不撤销切换。旧实例已经关闭、仅终结通知报错时，应用仍发布新引用并报告通知错误，避免当前引用停留在已关闭实例上。

历史与有效上下文对外只读，修改通过 Agent 命令进入，由 SDK 维护记录与投影的一致性。同一 Agent 至多一个改变历史或推进执行的独占活动；对话运行、继续运行和手动压缩共享忙碌范围，自动压缩、重试及其等待属于当前活动的内部阶段。工具批次内部可以并行。这一边界避免多个活动竞争提交历史；具体接纳规则见下文。

普通 prompt 与 continue 在整个活动忙碌范围内拒绝新运行，最终通知阶段 prompt 的接纳例外见 [ADR-0011](0011-agent-awaited-event-listeners.md)。明确选择 steering 或 follow-up 的输入可以排队，手动压缩期间也可以通过队列入口接纳，不打断当前请求或工具批次；队列消费保持既有边界与 FIFO 模式。手动 compact 先取消并等待当前活动，完成后不自行消费队列。请求前自动压缩与重试等待同属活动范围，不因内层循环暂时空闲而允许另一运行。

abort 保留现有不等待的取消入口，信号覆盖当前对话、工具、自动或手动摘要及重试退避，并阻止本活动后续自动续行；空闲等待或关闭负责确认收尾。取消等待者不取消 Agent 自有活动的规则保留。取消不清空未消费队列，也不撤销已经消费入历史的消息。这适配统一活动所有权及被等待的公共通知，不把不同阶段的提前空闲或局部取消空隙作为契约。

`Agent.state.messages` 表示有效上下文，完整历史记录通过独立只读接口取得。这保留了完整记录与下一次对话所用内容的区别；压缩后有效上下文包含摘要和保留尾部，完整历史仍包含原始消息与压缩记录。

只读边界通过与内部历史隔离的快照落实，复用现有消息数据类型，读取容器只读；调用者修改取得的消息副本不会写回 Agent。消息输入接纳、历史及上下文读取、请求 hooks 和每个公共监听器的消息数据均与内部历史隔离。相比引入另一套深层不可变消息读取类型，这减少调用者的数据类型适配，代价是快照复制成本和消息对象 identity 契约变化。

Agent 使用 SDK 定义的数据型自定义消息，应用扩展数据须可由 JSON 表示；宿主将原有业务对象转换为该消息。消息内容参与默认模型转换、摘要与预算估算，应用元数据不因此送入模型。相比保留只要求 role 的任意 Python 对象协议，这使历史隔离与恢复含义有共同的数据边界，代价是已有自定义对象调用者需要转换。SDK 定义数据结构，不接管应用的 JSON 编解码；独立 loop 保留原有开放应用消息协议。

完整 Agent 历史中的应用扩展值统一使用可由 JSON 表示的纯数据，包括标准工具结果的 details 等；宿主将业务对象转换为数据。SDK 固定消息与记录仍使用其数据类型，纯数据要求针对内部扩展值。相比只收窄自定义消息、继续接受标准消息中的任意业务对象，这让所有历史消息的隔离与恢复遵循共同边界，代价是依赖宽类型扩展值的调用者需要转换。独立 LLM 与 loop 的宽类型契约、工具执行对象及长期 provider 资源不因此更改；JSON 编解码仍属于应用。

首版提供不触发模型的自定义消息提交命令：空闲时提交历史并刷新有效上下文，对话运行时延后到安全回合边界，顺序位于当前 assistant 与工具结果之后；手动压缩期间拒绝该命令。相比仅通过 prompt 或输入队列接纳，这保留宿主先补充上下文、稍后请求模型的能力，并使提交服从运行时顺序。它不开放任意历史替换或回填。

SDK 提供按提交顺序通知新增完整记录的历史提交事件，可以携带一批记录。coding-agent 在被等待的订阅回调中序列化并完成写入，不必从消息、压缩和配置等语义事件反推哪些动作产生记录。事件表示权威内存历史已经提交；磁盘保存由应用完成，回调成功不额外承诺断电后的持久性。保存错误向 SDK 传播，遵守 [ADR-0011](0011-agent-awaited-event-listeners.md) 的监听器故障收尾规则：停止继续推进并失败收尾，保留已提交的内存历史与已完成的压缩结果，不作为模型错误重试。相比应用吞掉保存错误并继续活动，这避免将保存失败的对话继续当作正常已保存会话；内存提交与磁盘保存仍无原子性，重开只读回实际保存的记录。

保存失败后，coding-agent 标记该会话未保存并暂停新运行或压缩，保留内存历史供重试保存或导出；成功保存当前完整历史后恢复接纳。相比继续执行、在后续写入时补齐失败记录，这先处理保存故障再产生更多历史。应用仍可关闭或切换会话，但必须保留未保存的旧历史，不能仅追加新记录而留下缺口。此接纳限制属于应用，SDK Agent 不因此进入永久故障状态。

宿主可以在运行中变更模型、thinking level 与活动工具集合，后续请求准备时读取新配置；已准备的请求及其工具批次继续使用对应配置。本次压缩在开始时捕获模型与压缩配置，中途变更影响后续压缩。配置变更通过运行时接口协调相应的记录、声明和事件。

首版提供同一 Agent 上命名基础指令 section 的更新入口。宿主重新加载资源后可以在忙碌时更新期望配置，已开始的本次 prompt 保留基础指令快照，下一次新 prompt 按差异同步历史。section 按名称替换或删除，裸系统 content 仍按历史累加。相比更新资源后重建 Agent，这减少实例替换和订阅重绑；代价是配置生效边界不同，基础资源指令更新不等于模型或活动工具的逐请求更新。文件发现、加载与 reload 仍属于宿主，Agent 不自行监控资源。

手动压缩在对话运行期间调用时，先协作中止并等待旧活动收尾，再开始压缩。成功后追加压缩记录并重建有效上下文；提交前取消或失败不追加本次压缩记录。手动压缩保留未消费的输入队列，完成后不自行恢复被打断的对话或消费队列。摘要请求使用选定的暂时性模型错误重试策略，维护自己的重试计数。

保留内层 `agent_start` / `agent_end`，并以 `agent_settled` 表示整个对话活动收束；一次活动可包含多个内层循环。手动压缩有独立的开始、结束事件，自动压缩结束不表示对话活动结束。相比重定义现有 `agent_end`，这保留循环终结与运行时活动终结的区别；公共监听器继续被逐个等待，终结回调的接纳与等待规则见 [ADR-0011](0011-agent-awaited-event-listeners.md)。

SDK 提供永久关闭 Agent 实例的生命周期操作：开始关闭后停止接纳新工作，协作中止并等待当前活动收尾；关闭后历史仍可读取或导出，但旧引用不能再次启动工作。这比仅由应用中止、等待和解绑增加了明确的实例终态，防止已经退出的实例重新接纳工作。Agent 拥有已开始的关闭，取消某个调用方的关闭等待只结束该等待，不撤销关闭；其他调用方仍可等待同一次收尾。关闭继续遵守协作取消，不抢占工具或撤销副作用。

Agent 关闭收尾自身运行、任务与内部绑定；宿主注入的 provider client、连接池和长期工具资源仍由宿主管理。这样多个 Agent 可以共享注入资源，关闭其中一个实例不会释放其他实例仍在使用的资源；每次工具调用仍应收尾它自己持有的调用资源。

永久关闭不执行或自动迁移未消费队列，保留只读快照供宿主处理。未消费输入属于实例内存状态，只有被消费并进入对话后才成为历史；读取已保存的对话历史不自动恢复这些输入或未完成执行活动。

首版公开历史操作包含保存与恢复、新建与切换应用会话；分支导航、从历史节点 fork 及分支摘要留待后续。记录结构与公开操作范围分开决定，后续树操作的延后不要求记录丢弃稳定标识或投影所需关系。

首版保证应用能够保存并读回 omh 自身完整历史，恢复相同的有效上下文。与其他产品会话文件直接互读的版本、记录种类及字段兼容承诺留待后续；这一范围选择不改变完整历史与投影的记录语义。

SDK 定义历史记录的结构与恢复含义，coding-agent 负责序列化与磁盘读写。保存对象是完整历史记录，包含原始消息、压缩记录及其他已提交记录；恢复时应用将读回的记录交给 SDK，由 SDK 重建有效上下文。相比由 SDK 同时提供记录 JSON 编解码，这把文件表示与运行时领域结构分开，应用承担序列化映射与格式演进。

SDK 拒绝恢复关系不一致的已解码记录，包括重复标识、缺失必要引用或不存在的压缩保留边界，明确报告错误。相比省略无效项继续恢复，这避免悄然改变有效上下文。文件解析仍属于 coding-agent：无法解析的 JSONL 行被跳过；未换行的尾片段保留并补换行，避免后续追加与片段粘连。解析后的记录必须通过 SDK 一致性校验，跳过坏行不保证该文件能够恢复。具体记录 schema 与错误数据接口留待规格阶段。

首版移除 Agent 的同实例 `reset()` 入口，开始全新对话通过新 Agent；旧实例可关闭并保留历史读取。相比保留破坏性清空，这使首版的新建流程与实例绑定一致，避免再定义同一会话身份下清空完整历史及保存文件的规则。现有 reset 调用者需创建新实例并重绑订阅；这是一项显式的范围与兼容取舍，一实例一对话本身不要求删除 reset。

具体 Python 快照、读取/导出及恢复签名、记录 schema 在规格阶段展开。本决定不提供进程中断后的执行恢复。
