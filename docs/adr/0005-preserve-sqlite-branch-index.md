# SQLite 分段分支索引及已知性能限制

2026-09-22 整理：保留现有索引与已接受的性能边界；本次文档整理不引入索引优化或新的性能保证。

## Context

SQLite 通过分段缓存与 base branch/sequence 链组织分支查询。分叉时以相关前缀中最新 compaction 为复制边界；未压缩长历史仍可能复制 O(history) 索引行。

## Decision

当前版本保留这一实现，不承诺长历史分叉具有固定开销。查询必须无遗漏、无重复并保持正确分支历史。重新设计索引或要求所有历史预先压缩，均不属于本次整理范围。

## Consequences

调用者需要考虑未压缩长历史的分叉成本。优化应作为独立架构变更，以行为测试和性能证据评估；现有限制不能被文档改名掩盖。结构与代码入口见[对话树](../harness/conversation-tree.md)。
