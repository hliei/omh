# Agent 执行路径的模块边界

状态：已接受设计，尚未实施。

omh 将提供进程内有状态的 Agent，作为后续编码助手应用层的执行基础；现有 AgentHarness 的持久化执行路径收束到 `omh.agent.durable`。采用 `durable` 命名，是为了让模块边界直接表达事务、恢复与副作用处理保证。两条路径分别保留自己的执行契约，不因模块整理而改变现有持久化行为。

Session／Memory、持久化 runtime、结构操作和现有 harness 工具随持久化路径归位；SQLite 保持独立后端边界。共享类型与机制仅在语义相容时复用。具体声明与迁移清单在规格中展开，本决定不授权实现。

## 正式与实验性能力

进程内 Agent 及其后续编码助手应用层是正式建设主线；`omh.agent.durable` 定位为实验性能力。实验性定位允许其接口继续演进，不放宽已有事务、恢复和副作用处理契约，也不免除迁移时的行为回归验证。这里的正式主线是产品方向，不表示尚未实现的能力已交付或已有稳定版本承诺。

## 导入迁移

传统 Agent 使用 `omh.agent` 的主要公开入口，实验性持久化能力从 `omh.agent.durable` 显式导入。本次直接迁移被归位的旧入口，不保留兼容别名；仓库内调用、测试与文档同步更新，仓库外消费者需要修改导入。这一取舍使正式与实验性 API 边界清晰，避免持续维护旧入口。

## 执行核心

Agent 调用可独立使用的 agent loop；AgentHarness 继续使用持久化 runtime。两条执行路径各自负责状态推进、队列、事件生命周期和取消，不以 Memory Session 包装实现传统 Agent，也不在本次抽取统一执行内核。基础类型与辅助机制仅在语义相容时共享。代价是分别维护与验证两套循环；收益是传统运行行为与持久化事务、恢复及副作用保证均有明确边界。

## 首次建设范围

本次设计覆盖有状态 Agent、可独立调用的模型与工具循环、请求与回合及工具扩展点、流式事件，以及必要的类型和模型输入支持；同时规划现有持久化模块归位与行为回归验证。这样后续应用层可以在完整执行核心上建设，而不必先承担核心循环的职责。

新增路径的应用会话编排、会话文件保存、应用级自动重试和压缩策略、扩展系统、资源发现与编码助手产品集成留到后续阶段。现有持久化路径的相应能力继续保留。本次不提供两条运行路径之间的切换或会话转换。

## Agent 运行所有权与取消

Agent 拥有已启动的进程内运行。取消等待 `prompt`、继续运行或等待空闲的调用方，只结束该调用方的等待，不自动中止 Agent；显式 `abort` 才请求中止当前运行。运行及其终结监听器收尾前，Agent 仍处于忙碌状态。应用若希望超时同时停止执行，必须显式请求中止；停止等待之后，模型与工具仍可能继续执行。

取消信号要求模型与工具协作响应，不承诺抢占执行或撤销已发生的副作用。

独立低层 loop 按入口区分执行所有权。直接执行的异步入口由调用方拥有，取消其 task 会中断循环，不保证完整的回合及运行终结事件；需要协作取消收尾时，调用方应发送取消信号并等待循环完成。事件流入口拥有独立生产者，停止读取事件不自动停止执行，调用方通过显式取消信号请求生产者停止。Agent 的取消等待规则不改变低层直接执行入口的所有权。
